# 共用教材维护规范

更新：2026-10-15。用户要求先准备章节教材，再边读边问，避免教学主线散落在聊天记录中。

内容写作以 `AGENTS.md` 中“教学内容编写规范”为准，包括读者基础、递进解释、连续案例、分层阅读、代码讲解、答疑回写与发布检查。本文件补充协作和维护流程，章节骨架见 `templates/CHAPTER-TEMPLATE.md`。

## 文档入口

- 阅读：本地 MkDocs 文档站；源码首页 `docs/index.md`。
- 总学习分类及画像：`LEARNING-HUB.md`。
- 教学正文：`docs/NN-模块/`，每章一份 Markdown。
- 实际进度、答题证据、问题停车区：`learning/NN-模块/PROGRESS.md`。
- 聊天负责答疑、练习反馈与推进判断；完整知识正文必须落入教材。

## 开章前的工作

1. 读已有进度和用户最新问题，确认本章范围与前置知识；不把用户反馈“没有问题”等同于通过练习。
2. 先写完整章节；一次只准备当前章，按需要预备下一章，不预写所有未来章节。
3. 更新模块首页目录，章节正文首部说明“教材已准备；学习状态见进度记录”。
4. 构建检查成功后，给用户章链接，说明从哪个小节开始。本轮可以给 1–3 道理解题，不再把全部正文复制到聊天中。
5. 用户阅读、提问和练习期间保持章节结构稳定，不随意重排或改小节名。

## 完整章节应包含什么

参照 `templates/CHAPTER-TEMPLATE.md`：

- 标题、稳定章节编号、学习目标、前置知识和大致阅读时间。
- 从具体场景开始，解释对象、用途和流程；第一次出现术语先解释，再继续使用。
- 充分正文：从直觉到机制、分步骤例子、必要的图/表/代码。不能用几条提纲代替教学内容。
- 技术章给必要的运行方式、预期结果、错误排查；暂不依赖环境的读代码章明确说明。
- 业务章明确合成案例假设，区分通用业务知识与具体用友版本的实现。
- 易混点与常见错误，以及独立练习。参考答案放入折叠区，并给推理过程。
- 本章检查清单、相关来源、章末“阅读中产生的答疑”。尚未有答疑可写“暂无”。
- 避免不必要的知识扩展；必要前置写短注释并指向后续模块。

## 边学边问

- 用户可用“00-01 §2 看不懂”“01-01 的例子 B 为什么这样”定位；也接受自然语言，不强求记编号。
- 回复时先说明定位到哪个小节，再解释；有助于后续阅读的说明补回正文附近，或写入章末答疑并指回正文。
- 对跨章问题先给足以理解当前内容的短答，记录后续位置；只有用户明确要求才深入展开。
- 一轮答疑结束说明返回当前哪一节；不自动开始下一章。
- 用户做练习后在 PROGRESS.md 记录实际证据、错误与下次阅读位置；记录中保存“当前章节/当前小节/待后续解释”。
- 用户可选择先读、先问或做练习；不以练习通过作为继续阅读的强制门槛。用户主动推进时尊重其选择，未验证部分继续如实记录。
- 修正教材中的事实或代码错误时明确标注，不静默改变已使用练习的题意。

## 来源、代码与展示

- 当前用友产品、接口、框架版本等内容先核实官方资料并直接链接，不推测内部技术栈。
- 代码涉及外部依赖时声明环境和版本；代码短小、可解释，使用合成数据。
- Markdown 使用标准标题、围栏代码和表格；站点支持提示块、折叠答案、代码复制和搜索。
- 内部章节用相对 Markdown 链接；已知外部链接使用完整 URL。
- 不写 `file://` 链接；不要把本机绝对文件路径作为网页导航。

## 本地预览与检查

首次环境安装（总对话已开始执行）：

```sh
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install -r requirements-docs.txt
```

启动：`bash scripts/serve-docs.sh`，或 `.venv-docs/bin/mkdocs serve --dev-addr 127.0.0.1:8765`。浏览 `http://127.0.0.1:8765/`。若已经运行，无需重复启动；源文件变更自动重建。服务退出后重新运行启动命令。

本次可复现依赖已记录于 `requirements-docs.lock.txt`；重建当前版本环境时可用 `.venv-docs/bin/python -m pip install -r requirements-docs.lock.txt`。

检查：`.venv-docs/bin/mkdocs build --strict`。日常教学只需写 Markdown，无需改站点代码。所有生成物与虚拟环境不进入教材源码。
